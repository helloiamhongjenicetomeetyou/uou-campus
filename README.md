# 울산대 캠퍼스 길찾기

**https://www.uou-campus.site**

울산대학교 무거캠퍼스 안에서 **두 건물 사이 가장 빠른 길**을 찾아 주는 웹 서비스.
큰길로만 돌아갈 때와 견줘 **보행로·계단으로 질러가면 얼마나 벌 수 있는지**를 같이 보여줍니다.

## 왜 지도 API 길찾기를 안 쓰나

카카오·네이버·구글 길찾기는 **캠퍼스 안을 모릅니다.** 차량 경로가 기본이고,
보행 경로를 준다 해도 학교 안쪽 보행로·계단·건물 사이 통로는 데이터에 없습니다.
정문에서 전기/컴퓨터공학관까지 찍으면 대학로를 따라 빙 도는 길이 나옵니다.

그래서 이 서비스는 **캠퍼스 보행망을 직접 그래프로 들고** 다익스트라를 브라우저에서 돌립니다.
인증키도 서버도 없습니다. 빌드 결과는 정적 파일 세 개뿐입니다.

## 좌표를 지어내지 않았습니다

처음에는 캠퍼스 안내도 그림의 픽셀을 아핀 변환해 좌표를 만들 생각이었습니다.
그런데 **OpenStreetMap 에 울산대 캠퍼스가 이미 실측으로 들어가 있었습니다** —
보행로, 계단, 건물 윤곽까지. 어림값을 쓸 이유가 없어졌습니다.

| 무엇 | 어디서 왔나 |
| --- | --- |
| 길 형상 (보행로 192 · 차도 195 · 계단 33) | OpenStreetMap [relation/9762419](https://www.openstreetmap.org/relation/9762419) |
| 건물 위치·이름 (42곳) | 같은 곳. 건물 폴리곤의 중심 좌표 |
| 계단 여부, 터널·지하 통로 | OSM `highway=steps`, `tunnel`, `covered` 태그 |
| 건물 번호·별칭 | 캠퍼스 **공식 안내도의 범례**를 옮김 ([`scripts/seed-campus.mjs`](scripts/seed-campus.mjs) 의 `KNOWN`). 좌표가 아닌 유일한 손 입력이라 아래에 따로 적어 둔다 |
| 정문·후문 이름표 | 대략 위치에서 **가장 가까운 실제 OSM 길 노드**를 찾아 이름만 붙임 |
| 건물 ↔ 길 접속선 (61개) | 건물 중심에서 가장 가까운 길까지 곧게 이은 **모형**. 실제 출입구가 아님 |
| 지름길 52개 구간 (약 2.1km) | 캠퍼스 안내도에 **노란색으로 칠해 둔 길**을 옮김 |

지도 데이터 © OpenStreetMap 기여자, [ODbL](https://www.openstreetmap.org/copyright).
화면 오른쪽 아래 `© OpenStreetMap` 표기는 ODbL 과 타일 사용 정책이 요구하는
최소 표기라 지울 수 없습니다.

### 건물 번호는 손으로 얹은 값입니다

좌표와 길 형상은 OSM 실측이지만, **호관 번호는 사람이 표로 쳐 넣은 것**입니다
([`KNOWN`](scripts/seed-campus.mjs)). 그래서 틀릴 수 있고, 실제로 틀렸습니다 —
전기/컴퓨터공학관을 **17호관**으로 적어 뒀는데 울산대에 17호관은 없습니다.
**7호관**이 맞습니다. 재학생이 짚어 줘서 알았습니다.

지금은 캠퍼스 **공식 안내도의 범례**를 그대로 옮겨 마흔 개를 전부 맞춰 뒀습니다.
번호는 준공 순서라 이웃한 번호가 캠퍼스 반대편에 있고, **16 다음이 18** 처럼 중간에
비는 자리도 있습니다. 규칙으로 짐작할 수 있는 값이 아니라는 뜻이라, 새 건물을 넣을
때도 반드시 안내도를 봐야 합니다.

### 화면에 안 적어 둔 것

예전에는 패널 아래에 "건물 좌표는 출입구가 아니라 중심" 같은 각주를 달아 뒀는데
지금은 뺐습니다. 그 단서는 아래 표와 [시간 모형](#시간-모형-srcroutingcostts) 절에만 있습니다.
**짧은 경로일수록 오차 비율이 큽니다.**

### 아직 없는 것

가짜로 채우느니 비워 뒀습니다. 전부 편집 모드에서 채울 수 있습니다.

| 없는 것 | 왜 |
| --- | --- |
| 교수연구동(11) · 동아리관 I(13) · 학군단(21) · 동아리관 II(31) · 청운학사 문수관(33) | 안내도에는 있지만 OSM 에 아직 안 올라와 있습니다 |
| **실내 통과 구간 0개** | OSM 에 캠퍼스 건물 내부 통로가 하나도 없습니다. 「건물 안으로 질러가기」 토글이 꺼져 있는 이유입니다 |
| 문수관 → 교수연구동 지름길 | 안내도에 칠해져 있지만 **교수연구동이 OSM 에 없어** 지날 곳으로 적을 수가 없습니다 |
| 건물 출입구 | 건물 **중심** 좌표만 있습니다. 그래서 짧은 경로일수록 오차 비율이 큽니다 — [편집 모드에서 넣을 수 있습니다](#출입구를-넣는-법) |
| 계단 층수 | OSM 에 `step_count` 가 없어 거리로만 셈합니다 |

### 지름길을 어떻게 넣었나

캠퍼스 안내도에 노란색으로 칠해 둔 길이 있습니다. 이건 OSM 에 없는, 다녀 본 사람만 아는 정보입니다.

**그림의 픽셀을 위경도로 옮기는 방식은 쓰지 않았습니다.** 눈으로 읽은 픽셀은 오차가
수십 미터라 엉뚱한 길에 딱지가 붙습니다. 대신 **노란 선이 지나는 곳을 순서대로** 적어 두고
([`scripts/seed-campus.mjs`](scripts/seed-campus.mjs) 의 `SHORTCUT_CORRIDORS`),
실제 보행망 위에서 그 사이를 최단거리로 이어 붙입니다. 결과가 반드시 실재하는 길에 얹히고,
지어낸 좌표가 하나도 안 생깁니다.

| 갈래 | 길이 |
| --- | --- |
| 기숙사에서 공대로 내려오는 길 (청운학사 무거관 → 국제관 → 건축관) | 416m |
| 건축관에서 해송홀로 빠지는 길 (→ 공학행정관 → 해송홀) | 394m |
| 공대 세로축 (공학행정관 → 화학공학관 → 전기/컴퓨터공학관 → 문수관) | 397m |
| 정문에서 캠퍼스 안쪽으로 (정문 → 아산도서관 → 행정본관 → 문수관) | 892m |

지날 곳은 **건물이 아니라 그 옆 길목**으로 스냅합니다. 건물끼리 이으면 경로가 건물 중심으로
끌려 들어가서, 옆을 지나가는 통과 길이 아니라 건물로 들어가는 길에 딱지가 붙습니다.

사람이 눈으로 읽은 것이라 **틀릴 수 있습니다.** 화면에서 보고 다르면 위 표를 고치거나,
편집 모드에서 선을 눌러 지름길을 켜고 끄면 됩니다.

### 지름길 이득은 따로 계산합니다

표시와 별개로, 같은 두 지점을 두 번 풉니다.

1. 보행로·계단을 다 쓰는 경로
2. **차도만** 따라 도는 경로 (`roadsOnly`)

둘의 차이가 곧 질러가서 번 시간입니다. 청운학사 무거관 → 전기/컴퓨터공학관은
큰길로 8분, 보행로와 계단을 타면 6분 — **2분 · 145m** 를 법니다.

### 빠른 길과 아는 길이 다를 수 있습니다

「지름길 우선」과 「최소시간」의 답이 늘 같지는 않습니다.
청운학사 무거관 → 문수관은 안내도의 노란 길로 가면 9분 655m,
계산이 고른 길로 가면 7분 566m — **노란 길이 2분 느립니다.**
계단을 57m 타기 때문입니다(다른 길은 11m).

둘 다 보여 주는 게 이 화면의 요지입니다. 계단 배수 2.2 는 측정값이 아니라 추정이라,
실제로 걸어 보면 노란 길이 맞을 수도 있습니다.

## 경로를 어떻게 고르나

간선 비용이 음수가 될 일이 없어 A\* 대신 다익스트라로 충분합니다
([`src/routing/dijkstra.ts`](src/routing/dijkstra.ts)).

### 세 가지 기준

| 기준 | 최소화하는 값 |
| --- | --- |
| **최단거리** | 걷는 거리(m) |
| **최소시간** | 걸리는 시간(초) — 바닥에 따라 같은 거리도 다르게 셈 |
| **지름길 우선** | 시간. 다만 표시된 지름길은 **0.45배**로 쳐서 아는 길로 붙인다 |

「지름길 우선」의 할인율을 0 으로 두면 지름길만 골라 타느라 터무니없이 도는 길이 나옵니다.
0.45 는 "조금 돌더라도 아는 길로" 정도입니다.

표시된 지름길이 하나도 없으면 그 칩은 아무 일도 못 하므로 아예 안 보입니다.

답이 다를 때만 다른 기준의 경로를 **주황 점선**으로 지도에 겹쳐 보여 줍니다.

### 시간 모형 ([`src/routing/cost.ts`](src/routing/cost.ts))

평지 보행 속도 **1.3m/s** (4.7km/h) 를 기준으로 바닥마다 느려지는 배수를 곱합니다.

| 바닥 | 배수 | 들어설 때 붙는 손해 |
| --- | --- | --- |
| 보행로 · 차도 옆 | 1.0 | — |
| 비탈 | 1.35 | — |
| 계단 | **2.2** | 4초 |
| 건물 안 | 1.15 | 12초 (문 열고, 사람 피하고) |
| 횡단 | 1.0 | 10초 (신호 대기) |

**이 숫자들은 측정값이 아니라 추정입니다.** 실제로 걸어 보고 고칠 자리입니다.

### 옵션

- **건물 안으로 질러가기** — 끄면 실내 구간을 아예 안 씁니다. 문 닫히는 시간용

전에는 「비 피해 가기」도 있었는데 뺐습니다. 캠퍼스 안에 가려진 구간이
터널 5개뿐이라 켜도 경로가 그대로였습니다. 있으나 마나 한 스위치는 없느니만 못합니다.

## 화면 쓰는 법

- 출발·도착은 **이름·별칭·건물 번호** 아무거나로 찾습니다. `7`, `전컴관`, `ICT융합학부` 가 다 같은 곳입니다
- 지도 위 표시를 눌러도 됩니다. 처음 누른 곳이 출발지입니다
- **현위치에서 출발** — 쓸 만큼 다듬어진 첫 좌표가 잡히면 가장 가까운 **길목**을 출발지로
  세웁니다. 이미 출발지를 골라 뒀으면 덮어쓰지 않습니다. 길목에는 이름이 없어서
  `청운학사 무거관 근처` 처럼 가까운 건물 이름을 빌려 부릅니다
- 안내문은 크게 꺾는 자리만 남기고, 그 자리 **45m 안의 건물 이름**을 표지로 붙입니다
  ("건설환경공학관 앞에서 오른쪽으로 50m")

### 폰에서는 화면이 단계마다 바뀝니다

폰에서 이 앱의 본론은 지도인데, 손바닥만 한 화면에서 아래 시트가 3/4 을 물고 있으면
지도에서 아무것도 고를 수 없습니다. 그래서 넓은 화면과 좁은 화면이 모양만 다른 게 아니라
아예 다르게 움직입니다.

| 단계 | 화면 |
| --- | --- |
| **고르는 중** | 시트가 펼쳐집니다. 출발·도착 칸을 누르면 **전체 화면 장소 목록** |
| **지도에서 고르기** | 시트가 화면 밖으로 내려가고 지도만 남습니다 |
| **경로 나옴** | 시트가 저절로 접혀 요약 한 줄만 남고 지도가 화면을 거의 다 씁니다 |
| **안내 중** | 위쪽에 다음 동작 하나, 지도는 현위치를 따라갑니다 |

- **전체 화면 목록** ([`src/components/PlacePicker`](src/components/PlacePicker)) — 검색칸,
  건물 번호순 목록, 별칭, 현위치에서 얼마나 먼지. 출발지를 고르면 도착지 목록으로 곧바로
  넘어갑니다. 반대편에 이미 들어가 있는 곳은 눌러도 경로가 없으니 눌러 둡니다
- **지도에서 고르기** — 캠퍼스 전체를 맞춰 준 다음, 건물을 눌러도 되고 **그 근처를 대충
  눌러도** 120m 안에서 가장 가까운 곳이 잡힙니다. 지름 22px 짜리 점을 손가락으로 맞히라는
  건 무리라서입니다
- **시트 손잡이** — 끌어 접고 펴고, 그냥 눌러도 뒤집힙니다. 접었을 때 남기는 높이는
  숫자를 박아 두지 않고 손잡이 칸을 실제로 재서 씁니다 (아이폰 홈 바 자리까지 포함)
- 손으로 잡아 둔 시트 자리는 **그 구간을 보는 동안만** 유지됩니다. 안내 목록을 읽으려고
  펴 뒀다가 다른 곳을 고르면 다시 접힙니다 — 지난 구간의 손짓을 새 구간에 물려 두지 않습니다

넓은 화면에서는 왼쪽 패널이 지도를 가리지 않으니 지금까지처럼 칸 밑에 붙는 드롭다운으로
고릅니다. 갈림길은 [`src/hooks/useMediaQuery.ts`](src/hooks/useMediaQuery.ts) 의 `usePhone()`
한 곳입니다.

## 걸으면서 따라가기

경로가 나오면 **안내 시작**이 생깁니다. 누르면 위치를 켜고(이미 켜져 있으면 그대로 쓰고)
걷는 화면으로 넘어갑니다. **현위치에서 출발**만 켜 두어도 진행 상황은 그대로 나옵니다.

- 위쪽 띠에 **다음에 할 동작 하나**만 크게 뜹니다 — "80m 뒤 / 오른쪽으로 꺾기".
  걸으면서 읽는 글은 한 줄이 넘어가면 안 읽힙니다. 문장 전체와 남은 목록은 아래 패널에 그대로 있습니다
- 남은 거리와 시간이 줄어듭니다. 도착 **15m** 안에 들면 도착으로 봅니다 —
  건물 좌표는 출입구가 아니라 건물 한가운데라 0m 를 기다리면 문 앞에서도 안 끝납니다
- 지나온 구간은 지도에서 **회색**으로 덮이고 남은 길만 초록으로 남습니다
- **안내 중에는 지도가 계속 위치를 따라갑니다.** 걸으면서 화면을 손으로 끌 수는 없습니다.
  배율은 위치가 처음 잡힐 때 한 번만 맞추고 그 뒤로는 손대지 않습니다 — 매번 다시 맞추면
  손으로 넓혀 본 화면을 몇 초마다 되돌려 놓는 셈입니다
- 안내를 안 켰을 때는 화면 밖으로 나갈 때만 지도가 따라옵니다. 안쪽에 있는 동안은
  안 건드립니다 — 매번 가운데로 끌어오면 지도를 들여다볼 수가 없습니다
- 경로에서 많이 벌어지면 벗어났다고 알립니다. 기준은 **35m 와 GPS 오차 반경의 1.5배 중
  큰 쪽**입니다. 건물 사이에서는 오차가 30m 를 넘기도 하는데, 고정값 하나로 자르면
  걷는 내내 경고가 깜빡입니다

위치를 경로에 붙이는 계산은 [`src/routing/progress.ts`](src/routing/progress.ts) 에 있습니다.
경로를 이루는 선분마다 최근접점을 구해 가장 가까운 하나를 고릅니다. 한 경로의 선분은
수십 개뿐이라 위치가 갱신될 때마다 다 훑어도 됩니다.

### 건물이 아니라 길목에 붙이는 이유

처음에는 현위치를 가장 가까운 **건물**에 붙였는데, 실제로 걸어 보면 못 씁니다.
캠퍼스 길 위 120곳을 뽑아 재 보니 이렇습니다.

| 무엇까지의 거리 | 중앙값 | 최댓값 | 35m 초과 |
| --- | --- | --- | --- |
| 가장 가까운 건물·출입구 | 44m | 170m | **70%** |
| 가장 가까운 길목 | 14m | 113m | — |

길 한복판에 서 있으면 가장 가까운 건물이 중앙값 44m 나 떨어져 있습니다.
열에 일곱은 현위치를 켜자마자 '경로에서 벗어남' 으로 잡혔다는 뜻입니다.

**다만 길목에는 이름이 없습니다.** 기숙사 앞에 서서 현위치를 켰는데 화면에
`현위치 근처` 라고만 떠 있으면, 앱이 나를 제대로 찾은 것인지 알 방법이 없습니다.
그래서 붙인 자리 **45m 안의 건물 이름을 빌려** `청운학사 무거관 근처` 로 부릅니다.
안내문에서 꺾는 자리를 부를 때 쓰는 것과 같은 표지입니다
([`landmarkNear`](src/routing/directions.ts)).

### 어림한 좌표로는 출발지를 잡지 않습니다

브라우저는 위치를 한 번에 알려 주지 않습니다. 와이파이와 기지국으로 **어림잡은
좌표를 먼저** 던지고, 위성이 잡히면 다듬어서 다시 던집니다. 그 첫 값은 수백 미터가
틀리기도 합니다.

그걸로 출발지를 잡으면 캠퍼스 반대편 건물이 조용히 들어앉습니다. 화면에는 점이 잘
찍혀 있으니, 왜 엉뚱한 길이 나오는지 알 수가 없습니다. 그래서 오차 반경이 **50m
안쪽으로 다듬어질 때까지 기다립니다** — 건물 하나가 대충 그 정도 크기고, 그 안쪽이면
어느 길목에 붙어도 같은 동네입니다. 기다리는 동안에도 점은 찍히고, 옆에 `±400m` 처럼
지금 얼마나 어림한 자리인지 적어 둡니다.

**시간이 초과돼도 기다림을 접지 않습니다.** 건물 안에서 첫 좌표가 30초를 넘기는 일은
흔하고, 그러고 나서 잡히기도 합니다. 전에는 여기서 기다림을 접어 버려서, 그 뒤에 좋은
좌표가 와도 출발지가 비어 있었습니다 — 점은 찍혀 있는데 길찾기는 시작되지 않는
상태였습니다. 되돌릴 수 없는 것은 **권한이 막힌 경우** 하나뿐입니다.

지도에는 오차 반경을 **파란 원**으로 그립니다. GPS 는 '여기' 가 아니라 '이 안쪽' 을
알려 주는 것이라, 점 하나만 찍어 두면 그 점이 곧 내 자리인 줄 알게 되고 건물 안에서
30m 씩 튀는 걸 앱이 고장 난 것으로 읽게 됩니다. 반경이 10m 보다 작으면 안 그립니다 —
현위치 점이 이미 그만큼을 덮습니다.

### 걷지 않고 확인하는 법

실시간 위치가 제대로 도는지 보려면 원래는 캠퍼스를 걸어야 합니다.
주소에 **`?sim=1`** 을 붙이면 가짜 위치를 흘려 넣는 조작줄이 나옵니다.

```
http://localhost:4173/?sim=1
```

출발지와 도착지를 고르고 **걷기** 를 누르면, 그 경로 위를 1.3m/s 로 지나가는 좌표가
진짜 GPS 와 똑같은 자리로 들어갑니다. ×1 · ×4 · ×16 으로 속도를 올려 전 구간을
몇 초 만에 훑어볼 수 있습니다.

일부러 옆으로 **4m 씩 흔들어 둡니다.** 오차가 0 이면 경로에 끌어당기는 계산이
도는지 안 도는지 알 수가 없어서입니다. 화면의 「경로에서 ○m」 이 그 값입니다.

시뮬레이터는 `setInterval` 로 돕니다. `requestAnimationFrame` 은 탭이 뒤에 있거나
화면이 멈춘 환경에서 아예 안 불려서 시뮬레이터가 그대로 서 버립니다.

### 진짜 GPS 로 확인하려면

`navigator.geolocation` 은 **보안 컨텍스트에서만** 동작합니다. `localhost` 는 되지만
`pnpm dev --host` 로 띄운 뒤 휴대폰에서 `http://192.168.x.x:5173` 로 열면 막힙니다.

| 방법 | 되는 것 |
| --- | --- |
| Vercel 에 올려서 휴대폰으로 열기 | 실제로 걸으면서 전부 확인 |
| 크롬 개발자도구 → Sensors → Location | 좌표 하나를 고정으로 흉내. **움직이지는 않습니다** |
| `?sim=1` | 움직임까지 확인. 책상에서 되는 유일한 방법 |

## 홈 화면에 설치하기

브라우저 탭이 아니라 앱처럼 씁니다. 주소창이 사라지고, 아이콘이 홈 화면에 남고,
**신호가 끊겨도 길찾기가 그대로 됩니다.**

| 기기 | 방법 |
| --- | --- |
| 안드로이드 크롬 · 데스크톱 크롬/엣지 | 지도 **오른쪽 위 「앱 설치」** 를 누릅니다 |
| iOS 사파리 | 같은 자리를 누르면 「공유 → 홈 화면에 추가」 안내가 뜹니다 |

크롬 계열은 `beforeinstallprompt` 를 잡아 뒀다가 버튼을 누를 때 띄웁니다.
iOS 사파리에는 그런 이벤트가 없어서 안내만 합니다. 이미 설치한 상태면 버튼이 안 보입니다.

단추는 지도 오른쪽 위에 **따로** 서 있습니다
([`InstallButton`](src/components/InstallButton/index.tsx)). 전에는 길찾기 패널 머리에
「편집」과 나란히 있었는데, 폰에서 시트를 접으면 그 줄이 접힌 자리 아래로 내려가 아예 안
보였습니다. 하루에 한 번 누를 일도 없는 단추 둘이 제목 옆을 물고 있을 이유도 없습니다.

- 왼쪽 위는 패널(넓은 화면)과 상단 안내 띠(좁은 화면)가, 오른쪽 아래는 Leaflet 배율
  단추와 출처 표기가 씁니다. 남는 자리가 오른쪽 위입니다
- 걷는 중이나 지도에서 곳을 고르는 중에는 상단 띠가 그 자리를 쓰므로 **비켜 줍니다** —
  정작 봐야 할 안내를 설치 단추가 가리면 안 됩니다
- `×` 로 접으면 이번 방문에는 다시 안 나옵니다. 새로 열면 다시 나옵니다

### 끊겨도 되는 이유

캠퍼스 안은 신호가 잘 죽습니다. 그래서 [`public/sw.js`](public/sw.js) 가 세 가지를 들고 있습니다.

| 무엇 | 방식 |
| --- | --- |
| 앱 껍데기 (`/`) | 새로 받아 보고, 안 되면 들고 있던 것 |
| 빌드 산출물 (`/assets/*`) | 이름에 해시가 붙어 안 바뀐다 — 있으면 그대로 |
| 이름이 그대로인 파일 (매니페스트·아이콘) | 있으면 바로 내주고 뒤에서 새로 받아 둔다 |
| 지도 타일 | 위와 같음. 최대 500장 |

**이름이 안 바뀌는 파일까지 캐시 우선으로 잡으면 안 됩니다.** 강조색을 고쳐 올렸더니
화면은 새 색인데 매니페스트만 옛 색으로 남는 일이 실제로 있었습니다. 해시가 붙은
`/assets/*` 만 캐시 우선이고, 나머지는 내주면서 뒤에서 갱신합니다.

**그래프는 번들에 들어 있어 애초에 네트워크를 안 탑니다.** 한 번 본 자리라면
비행기 모드에서도 길찾기가 됩니다.

타일은 다른 출처라 `no-cors` 로 나가고 그 응답은 opaque 입니다 — `status` 가 0,
`ok` 가 false 라서 `ok` 만 보고 거르면 한 장도 안 담깁니다. `cache.put` 은 opaque 도 받습니다.

서비스 워커는 **빌드본에서만** 등록합니다. 개발 중에 끼면 고친 코드 대신 캐시가 나옵니다.

```bash
pnpm build && pnpm preview   # 설치·오프라인은 여기서 확인
```

## 편집 모드

주소에 `?edit=1` 을 붙이거나 오른쪽 위 **편집** 을 누릅니다.
고친 내용은 곧바로 브라우저에 저장돼서 새로고침해도 안 날아갑니다.

- 표시를 **끌어 옮기면** 좌표가 맞춰집니다 (`precision: 'surveyed'`)
- 지도 **빈 곳을 누르면** 길목이 새로 생깁니다
- 고른 곳의 **종류**를 건물 · 시설 · 출입문 · 길목 중에서 고릅니다
- **좌표 옆 딱지**를 눌러 `근사치` ↔ `맞춘 좌표` 를 뒤집습니다
- 노드를 고르고 **길 잇기** → 이을 곳을 누르면 간선이 생깁니다
- **선을 누르면** 그 길의 바닥·지름길·비 가림·출처를 고칩니다
- 길목은 **확대(z17 이상)해야** 보입니다. 안 그러면 점 삼백 개가 지도를 덮습니다

### 출입구를 넣는 법

건물 좌표는 출입구가 아니라 **건물 중심**입니다. 그래서 짧은 경로일수록 오차 비율이
큽니다. 실제 문 자리를 넣으려면 이렇게 합니다.

1. 지도에서 문 앞을 눌러 지점을 만듭니다 (길목으로 생깁니다)
2. **종류**를 `출입문` 으로 올리고 이름을 넣습니다 — 「인문관 정문」 처럼
3. 걸어 보고 찍은 게 아니라 안내도만 보고 찍었다면 **`근사치`** 로 표시해 둡니다
4. **길 잇기** 로 그 문과 가장 가까운 보행로를 잇습니다

종류를 길목 그대로 두면 안 됩니다. **길목만 장소 목록에서 빠지기 때문에**
([`places`](src/routing/graph.ts)) 이름을 넣어도 검색에 안 나오고, 평소 지도에서도
안 보입니다 — 찍어 둔 사람만 아는 점이 됩니다.

문을 따로 만들기 번거로우면, 건물에 붙은 **접속선의 반대쪽 길목을 문 앞으로 끌어다
놓는** 방법도 있습니다. 새 지점 없이 경로가 실제 문 쪽으로 빠져나갑니다.

### 모두에게 보이게 하기

고친 내용은 원래 **고친 사람 브라우저에만** 남습니다 (`localStorage` 의
`campus-route:graph`). 앱은 받아 주는 서버 없이 도는 정적 파일이라, 남이
`?edit=1` 로 들어와 캠퍼스를 헤집어 놔도 다른 사람 화면은 멀쩡합니다.
대신 잘 고친 것도 혼자만 봅니다.

편집 패널의 **모두에게 저장** 이 그 사이를 잇습니다.

1. 암호를 넣고 누르면 [`/api/publish`](api/publish.ts) 로 문서를 보냅니다
2. 서버가 암호를 맞춰 보고, 문서가 성한지 검사하고
3. GitHub 에 [`src/data/campus.json`](src/data/campus.json) 을 커밋합니다
4. Vercel 이 그걸 받아 다시 배포합니다 — **1분쯤 뒤부터 모두가 같은 지도를 봅니다**

저장 자리를 깃으로 잡은 것은 이력 때문입니다. 누가 언제 뭘 고쳤는지가 커밋으로
남고, 잘못 올렸으면 **`git revert` 한 줄**이면 됩니다. 이력도 되돌리기도 따로
만들 게 없습니다.

#### 통째로 덮어쓰는 자리라 들어오는 값을 안 믿습니다

실수로 빈 문서를 올리면 캠퍼스가 사라진 채 배포됩니다. 되돌릴 수는 있지만 애초에
막는 편이 낫습니다. 서버가 이런 것들을 거절합니다.

| 거절하는 것 | 왜 |
| --- | --- |
| 노드 50개 · 간선 50개 미만 | 실수로 지운 문서 |
| 캠퍼스를 넉넉히 둘러싼 상자 밖 좌표 | 잘못 들어온 값 |
| `id` 가 없거나 겹치는 노드 | 그래프가 깨집니다 |
| 없는 곳을 가리키는 간선 | 같은 이유 |
| 4MB 초과 | 정상적인 문서가 아닙니다 |

암호는 길이가 달라도 **같은 시간을 쓰게 맞춰** 비교합니다. 빨리 틀리는 자리로
한 글자씩 알아내는 짓을 막기 위해서입니다.

#### 서버에 넣어 둘 값 (Vercel → Settings → Environment Variables)

| 이름 | 값 |
| --- | --- |
| `EDIT_PASSWORD` | 저장할 때 물어볼 암호. 아무 데도 안 쓰는 값으로 |
| `GITHUB_TOKEN` | 이 저장소의 **Contents 읽기·쓰기** 권한만 가진 fine-grained 토큰 |
| `GITHUB_REPO` | (선택) `owner/repo`. 없으면 이 저장소 |
| `GITHUB_BRANCH` | (선택) 없으면 `main` |

**`VITE_` 를 붙이면 안 됩니다.** 그걸 붙이면 브라우저로 실려 나가 누구나 읽습니다.
셋 다 서버에서만 읽는 값입니다.

#### 알아 둘 것

- 저장한 뒤에도 **내 화면은 내 브라우저 사본**을 계속 봅니다. 배포된 것을 보려면
  「고친 것 버리고 시드로 되돌리기」를 누르거나 다른 기기에서 여세요
- 개발 서버(`pnpm dev`)에는 이 함수가 없습니다. 배포본에서만 됩니다
- 저장할 때마다 커밋 하나와 배포 한 번이 돕니다. 걸어 다니며 스무 번 누르지 말고,
  한 바퀴 돌고 나서 한 번 저장하세요

파일로 주고받고 싶으면 **campus.json 받기** 로 내려받아
[`src/data/campus.json`](src/data/campus.json) 을 덮어써도 똑같습니다.

⚠️ 그렇게 손으로 넣은 값은 **시드를 다시 돌리면 날아갑니다**. 건물 번호처럼
[`KNOWN`](scripts/seed-campus.mjs) 으로 표현되는 것은 시드 쪽에 넣어야 살아남습니다.
그래서 [`pnpm seed`](#데이터-다시-만들기) 에 `--force` 가드가 걸려 있습니다.

## 데이터 다시 만들기

```bash
node scripts/fetch-osm.mjs        # OSM 원본 받기 → scripts/osm-campus.json
node scripts/seed-campus.mjs      # 원본 → src/data/campus.json
```

`osm-campus.json` 은 저장소에 함께 둡니다. 네트워크 없이도 시드를 다시 돌릴 수 있고,
좌표가 무엇을 근거로 정해졌는지 나중에도 확인할 수 있습니다.

`seed-campus.mjs` 는 이미 있는 `campus.json` 을 덮어쓰지 않습니다.
편집 모드에서 맞춘 값을 날릴 수 있어서입니다. 정말 다시 만들려면 `--force` 를 붙입니다.

시드가 하는 일:

1. 캠퍼스 경계 안에 걸치는 길만 남긴다 (광선 쏘기로 점-다각형 판정)
2. 좌표가 정확히 겹치는 점을 같은 노드로 본다 — OSM 은 교차점에서 노드를 공유한다
3. **이웃이 둘뿐인 점은 접어서** 꺾임점(`via`)으로 바꾼다. 안 접으면 노드가 1,700개 나온다
4. 건물을 가장 가까운 길에 매단다. 그 길이 보행로뿐이면 **차도에도 한 가닥 더** 매단다
   — 안 그러면 기숙사처럼 보행로에만 붙은 건물은 차도 비교가 아예 불가능해진다
5. 안내도의 노란 지름길을 지나는 곳 순서대로 풀어서, 그 위 간선에 `shortcut` 딱지를 단다
6. 이어지지 않은 조각을 버리고 가장 큰 덩어리만 남긴다

남서쪽 **울산과학대학교 서부캠퍼스**가 경계 안쪽에 물려 있습니다.
1공학관·2공학관·대학회관·용접기술센터·산학협력관은 울산대 건물이 아니라 `NOT_OURS` 로 뺐습니다.

## 배포

**HTTPS 여야 합니다.** `navigator.geolocation` 도 서비스 워커도 보안 컨텍스트에서만
동작해서, `pnpm dev --host` 로 띄우고 휴대폰에서 `http://192.168.x.x:5173` 으로 열면
위치·설치·오프라인이 전부 막힙니다. Vercel 에 올리면 셋 다 한 번에 풀립니다.

Vercel 정적 빌드. 리포지토리 루트가 곧 앱이라 Root Directory 설정이 필요 없고,
`pnpm build` → `dist` 는 Vite 프리셋이 잡습니다. 환경변수는 통계용 `VITE_GA_ID` 하나뿐이고,
그것도 없으면 없는 대로 돕니다 (아래 「통계」).

### 도메인

`www.uou-campus.site` 를 정본으로 씁니다. 도메인은 가비아에서 샀고 네임서버도
가비아에 그대로 둔 채, 레코드만 Vercel 로 돌렸습니다.

| 이름 | 종류 | 값 |
| --- | --- | --- |
| `uou-campus.site` | A | `216.198.79.1` |
| `www` | CNAME | Vercel 이 도메인 추가할 때 알려 주는 `*.vercel-dns-017.com` 값 |

apex 로 들어오면 Vercel 이 `www` 로 308 을 내주고, `http` 도 `https` 로 308 입니다.
둘 다 Vercel 쪽에서 알아서 하는 일이라 `vercel.json` 에 리다이렉트를 또 쓰면 안 됩니다.

**Vercel 도메인 화면의 `Proxy status: Unknown` 은 오류가 아닙니다.** 이 도메인 앞에
Cloudflare 같은 리버스 프록시가 끼어 있는지 판단이 안 된다는 뜻입니다. 지금은
네임서버가 가비아라 Vercel 이 확인할 길이 없어서 그렇게 표시됩니다. 프록시가 없는
게 맞고, 실제로 인증서도 HSTS 도 정상입니다.

코드에는 출처가 거의 박혀 있지 않습니다 — 매니페스트의 `start_url` 도 아이콘 경로도
전부 루트 상대라, 도메인을 또 바꿔도 고칠 것이 없습니다.

딱 한 군데 예외가 링크 미리보기(Open Graph) 태그입니다. 카톡·페이스북 크롤러는
**상대 경로를 못 읽어서** `og:url` 과 `og:image` 만 절대 주소로 적어 뒀습니다
([`index.html`](index.html)). 도메인을 바꾸면 이 두 줄은 손봐야 합니다.

[`vercel.json`](vercel.json) 에는 새로고침용 리라이트 말고 헤더 두 줄이 더 있습니다.

| 대상 | 왜 |
| --- | --- |
| `/sw.js` | `max-age=0` — 서비스 워커가 캐시에 갇히면 새 빌드가 영영 안 나갑니다 |
| `/manifest.webmanifest` | `application/manifest+json` 으로 못 박아 설치 판정이 흔들리지 않게 |

지도 타일은 `tile.openstreetmap.org` 를 직접 씁니다. [타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/)상
개인 프로젝트 수준이면 괜찮지만, 트래픽이 늘면 타일 제공자를 옮겨야 합니다
([`src/map/mapStyle.ts`](src/map/mapStyle.ts) 의 `TILE_URL` 한 줄).

## 통계

어디서 어디로 다니는지 알아야 고칠 자리가 보입니다. 사람이 한 번도 안 찾는 건물은 좌표를
다듬을 필요가 없고, **길이 없다고 뜨는 조합은 그래프에 빠진 길이 있다는 뜻**입니다.
그걸 보려고 Google Analytics 4 를 답니다 ([`src/analytics/gtag.ts`](src/analytics/gtag.ts)).

```bash
cp .env.example .env
```

```env
VITE_GA_ID=G-XXXXXXXXXX
```

애널리틱스 → 관리 → 데이터 스트림에서 받는 값입니다. Vercel 에서는 Project Settings →
Environment Variables 에 같은 이름으로 넣습니다.

**측정 ID 가 없으면 통계 코드가 번들에 아예 안 들어갑니다.** Vite 가 `import.meta.env` 를
빌드 때 값으로 박아 넣기 때문에, ID 가 비어 있으면 시작하자마자 되돌아가는 게 정적으로
드러나 그 아래가 통째로 털려 나갑니다 — 빌드해서 `googletagmanager` 를 찾아 보면 0 건입니다.
키 없이 클론해 온 사람도 그대로 돌릴 수 있어야 합니다.

붙지 않는 경우가 두 가지 더 있습니다.

- **개발 중** (`import.meta.env.PROD` 가 아닐 때) — 고치는 동안 새로고침한 수십 번이
  실제 방문으로 섞이면 숫자를 볼 수 없게 됩니다
- **추적을 원치 않는다고 브라우저가 말할 때** — `navigator.doNotTrack` 이나
  Global Privacy Control. 이때는 스크립트조차 받지 않습니다

### 무엇을 보내나

| 이벤트 | 언제 | 딸려 보내는 것 |
| --- | --- | --- |
| `route_search` | 경로가 나왔을 때 | 출발·도착 **이름**, 기준, 실내 허용, 거리·시간·지름길 거리 |
| `route_missing` | 두 곳 사이에 이어진 길이 없을 때 | 출발·도착 이름 |
| `place_pick` | 곳을 골랐을 때 | 어느 칸인지, 고른 방식(`list` · `map` · `map_near` · `geo`), 이름 |
| `place_pick_on_map` | 지도에서 고르기로 들어갔을 때 | 어느 칸인지 |
| `guide_start` · `guide_arrive` · `guide_stop` | 안내를 켜고 · 도착하고 · 끄고 | 구간 이름, 거리, 남은 거리 |
| `app_install_prompt` | 「앱 설치」를 눌렀을 때 | — |

**좌표와 위치 기록은 보내지 않습니다.** 걸은 자취를 남길 이유가 없고, 캠퍼스 안 위치는
곧 그 사람이 어디 있었는지입니다. 같은 구간을 다시 그릴 때마다 보내지도 않습니다 —
출발·도착·기준이 바뀔 때만 한 번입니다. 도착도 한 번만 셉니다 (문 앞에서 위치가 흔들리며
몇 번씩 들락거립니다).

서비스 워커는 이 요청에 손대지 않습니다. 같은 출처와 타일 호스트만 가로채도록 되어 있어
([`public/sw.js`](public/sw.js)) 다른 출처인 GA 는 그냥 지나갑니다.

`gtag` 를 만드는 자리에 화살표 함수를 못 쓴 것은 규칙을 어긴 게 아닙니다. 태그 쪽이
`arguments` 객체인지 보고 가르기 때문에 배열로 바꿔 넣으면 무시됩니다.

보행로·계단·지름길만 초록으로 앞세웁니다. 색은 데이터에만 쓰고 나머지는 물러납니다.

## 아이콘 다시 만들기

원본은 울산대 CI 워드마크 [`scripts/uou-logo.svg`](scripts/uou-logo.svg) 하나입니다.

```bash
pnpm icons     # → public/icon.svg · icon-192 · icon-512 · maskable-512 · apple-touch-180
```

가로로 긴 그림(가로세로비 1.66)이라 정사각 캔버스 한가운데 앉힙니다. 쓰임새마다
여백과 배경이 달라 세 벌을 따로 뽑습니다.

| 쓰임새 | 가로 비율 | 왜 |
| --- | --- | --- |
| `icon.svg` · 192 · 512 | 86% | 탭에서 작게 줄어드니 여백을 아낍니다. 모서리는 우리가 둥글립니다 |
| `icon-maskable-512` | 58% | 안드로이드가 제 모양대로 잘라 냅니다. 안쪽 원 안에 들어와야 합니다 |
| `apple-touch-icon` | 78% | iOS 가 직접 모서리를 깎습니다. 우리가 둥글리면 이가 나갑니다 |

`rsvg-convert` 가 있어야 합니다 (`brew install librsvg`).

### 원본에 숨어 있던 함정

CI 파일에는 **viewBox 밖에 놓인 외곽선 사본이 6개** 들어 있습니다. 원본 크기로 열면
잘려 나가서 안 보이지만, `<g transform>` 으로 옮겨 담으면 클리핑이 풀려 유령처럼
따라 나옵니다. 그래서 중첩 `<svg>` 로 원본 뷰포트를 그대로 만들어 씁니다.
